# Friend System

게임 내 소셜 기능을 위한 친구 추가 및 관리 시스템의 구조 설계 프로토타입

## 프로젝트 개요

게임 내 친구 시스템의 데이터 관리, 화면 구성 및 사용자 액션 처리 구조를 검토하기 위해 작성한 Unity/C# 기반 프로토타입입니다.

친구 데이터 관리와 UI 표현, 사용자 액션 처리를 역할별로 분리하여 각 구성 요소의 책임을 명확하게 하고, 기능 확장 및 UI 변경에 유연하게 대응할 수 있는 구조를 목표로 설계했습니다.

## 주요 구조

### Model / Data

#### `FriendInfo`

개별 친구의 기본 정보와 친구 관계 상태를 관리합니다.

- 유저 ID 및 닉네임
- 선호 구단 및 OVR
- 최근 접속 시간 및 온라인 상태
- 친구 관계 상태
- 콘텐츠별 순위 정보

#### `FriendSystemData`

친구 시스템 전체의 데이터를 관리합니다.

- 친구 목록 관리
- 최대 친구 수 관리
- 나의 친구 추가 코드 관리
- 친구 관계 상태 변경
- 상태별 친구 목록 조회
- 서버 JSON 데이터 파싱 및 초기화

### Controller / UI Flow

#### `UIPopupFriendList`

친구 목록 화면의 흐름을 관리하고 Model과 View 사이의 데이터를 연결합니다.

- 현재 선택된 친구 목록 탭 관리
- 친구 상태에 따른 데이터 조회
- 친구 목록 UI Item 생성 및 제거
- 친구 데이터와 UI Item 연결
- 친구 액션 요청을 받아 서버 요청 로직으로 전달

친구 목록 Item에서 발생한 사용자 액션은 `Action<FriendInfo, eFriendAction>` 콜백을 통해 상위 객체로 전달되도록 구성했습니다.

### View

#### `UIPopupFriendListItem`

개별 친구 정보를 화면에 표시하고 사용자 인터랙션을 상위 객체에 전달합니다.

- 친구 정보 표시
- 친구 수락 / 거절
- 친구 삭제
- 친구 요청 취소
- 사용자 액션을 `eFriendAction`으로 정의하여 상위 객체에 전달

## 주요 설계

### 1. 데이터와 UI 역할 분리

`FriendInfo`와 `FriendSystemData`는 친구 데이터와 상태를 관리하고, `UIPopupFriendList`와 `UIPopupFriendListItem`은 화면 구성과 사용자 인터랙션을 담당하도록 역할을 분리했습니다.

이를 통해 데이터 구조가 변경되거나 UI가 변경되는 경우 수정 범위를 분리할 수 있도록 설계했습니다.

### 2. 친구 상태 기반 데이터 조회

`eFriendState`를 기준으로 친구, 보낸 요청, 받은 요청을 구분하고, `FriendSystemData.GetFriendListView()`를 통해 현재 화면에 필요한 데이터만 조회하도록 구성했습니다.

### 3. UI Item과 상위 화면 간 이벤트 분리

`UIPopupFriendListItem`은 각 버튼의 동작을 직접 처리하지 않고 `Action<FriendInfo, eFriendAction>` 콜백을 통해 액션을 상위 객체에 전달합니다.

이를 통해 개별 UI Item은 친구 요청 처리 방식이나 서버 통신 방식에 의존하지 않고, UI 표현과 사용자 액션 전달에 집중하도록 구성했습니다.

### 4. 친구 상태 변경의 단일 진입점

친구 관계 상태 변경은 `FriendSystemData.UpdateFriendState()`를 통해 처리하도록 구성했습니다.

친구 상태 변경과 삭제의 데이터 변경 경로를 제한하여 상태 관리의 일관성을 유지하도록 설계했습니다.

### 5. 서버 데이터와 클라이언트 데이터 모델 분리

서버에서 전달되는 JSON 데이터를 `FriendInfo` 및 `FriendSystemData`에서 클라이언트 데이터 모델로 변환하도록 구성했습니다.

이를 통해 서버 응답 데이터를 콘텐츠에서 직접 다루기보다 클라이언트에서 사용하는 데이터 구조로 변환하여 활용할 수 있도록 했습니다.
